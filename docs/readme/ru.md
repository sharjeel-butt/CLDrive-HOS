# CLDrive

**Единый менеджер облачных файлов для HarmonyOS.**

CLDrive объединяет OneDrive, Google Drive и Dropbox в единый, последовательный файловый браузер. Управляйте всеми своими облачными аккаунтами из одного нативного приложения HarmonyOS — с межпровайдерными операциями, безопасной аутентификацией PKCE и расширяемой архитектурой, благодаря которой добавление нового провайдера сводится к написанию одного класса.

**Текущая версия:** 1.4.0

## ✨ Возможности

### Несколько аккаунтов, несколько провайдеров
- Вход в неограниченное число аккаунтов OneDrive, Google Drive и Dropbox
- Дерево в боковой панели группирует аккаунты по провайдерам
- Переключение между аккаунтами одним касанием
- Аватар, отображаемое имя и email для каждого аккаунта
- Выход прямо из строки активного аккаунта

### Единый файловый браузер
- Единообразный опыт для каждого провайдера
- **Списочный и сеточный режимы** с переключением одним касанием в верхней панели
- Навигация по папкам с кликабельной цепочкой навигации
- **Фильтры**: Все · Изображения · Видео · Документы · Аудио · Другое
- **Меню сортировки**: Имя (A–Z / Z–A), Новые, Старые, Крупнейшие
- Метаданные файла: имя, размер, относительная метка времени, иконка по типу
- Настоящие миниатюры, когда провайдер их предоставляет; иначе значки FileIcon
- Значок **«Общий доступ»** отмечает файлы и папки, которыми вы не владеете
- Обновление жестом вниз, состояния загрузки и обработка ошибок
- Поиск по активному аккаунту с запросами с задержкой (debounce)
- Автоматически заполняемые расширения файлов на основе MIME-типа

### Множественный выбор и пакетные операции
- Долгое нажатие на любой элемент для входа в режим выбора
- Выбрать все / Снять выделение
- Пакетные удаление, перемещение, копирование и скачивание
- Разрешение конфликтов: Пропустить все / Сохранить оба / Заменить все
- Панель действий выбора в порядке: **Копировать · Переместить · Скачать · Удалить**

### Панель задач
- Прогресс в реальном времени для загрузок, скачиваний, перемещений, копирований и удалений
- Четыре вкладки: **Все · Ожидают · Готово · Ошибки**
- «Ожидают» показывает всю поставленную в очередь партию до начала выполнения
- Операции сгруппированы по дате (Сегодня / Вчера / конкретные даты)
- Журнал сохраняется между перезапусками приложения (до 500 последних задач)
- Кольцевые индикаторы прогресса для каждой передачи
- Поддержка **повтора** для неудачных задач (↻ в строке и «Повторить все»)
- Иконка активности в верхней панели отражает состояние:
  - **Синий** — выполняются задачи
  - **Серый** — простой, нет истории
  - **Зелёный** — все задачи успешны
  - **Жёлтый** — есть и успехи, и ошибки
  - **Красный** — все задачи завершились ошибкой

### Офлайн-доступ
- Отметьте любой файл как **«Доступен офлайн»**
- Файлы хранятся в приватной песочнице приложения (`filesDir`)
- Открывайте офлайн-файлы системным просмотрщиком по умолчанию
- Коснитесь любого онлайн-файла, чтобы скачать его в кэш предпросмотра и открыть одним действием
- **Кэш для каждого аккаунта**: кэшированные файлы каждого аккаунта отслеживаются отдельно
- Очистка кэша для каждого аккаунта из боковой панели; размер и количество отображаются в реальном времени

### Обзор хранилища
- Карточка хранилища в боковой панели показывает квоту облачного диска для активного аккаунта
  - OneDrive: квота `/me/drive`
  - Google Drive: `storageQuota`
  - Dropbox: `get_space_usage`
- Полоса квоты становится красной при использовании выше 85%
- Раздел офлайн-кэша показывает количество элементов и общий размер для активного аккаунта

### Внешний вид
- Светлая, Тёмная и «Как в системе»
- Сохранённые предпочтения пользователя
- Полная поддержка темы на всех экранах, включая OAuth WebView
- Полный набор SVG-иконок, наследующих цвет темы во всём интерфейсе

### Безопасность по дизайну
- Поток Authorization Code в OAuth 2.0 с PKCE (S256)
- В приложении нет встроенных клиентских секретов (OneDrive и Dropbox используют чистый PKCE)
- Google требует клиентский секрет из-за типа OAuth-клиента «Web application»
- Токены хранятся в HarmonyOS Asset Store (разбиты на части, чтобы обойти ограничение в 1024 байта)
- Автоматическое обновление токена при истечении срока
- Проверка параметра state для предотвращения CSRF
- Выбор нескольких файлов копирует файлы в промежуточную область песочницы перед загрузкой, поэтому повторы работают после перезапуска приложения

### Скоро
- **WebDAV** — Nextcloud, ownCloud, Synology и любой WebDAV-сервер
- **Amazon S3** — объектное хранилище, совместимое с S3
- **Box** — облачное хранилище Box

Они отображаются в списке провайдеров с пометкой «Скоро».

## 🏗️ Архитектура

CLDrive построен вокруг абстракции провайдера. Слой UI никогда не обращается к API конкретного провайдера — он работает с интерфейсами, а фабрика предоставляет нужную реализацию во время выполнения.

```
UI (pages/components)
  → ViewModels
    → CloudProviderFactory
      → ICloudProvider implementations
        → Core (HttpClient, TokenStorage, PkceHelper)
```

Ключевые контракты:

- **`ICloudProvider`** — единый интерфейс, который реализует каждый провайдер
- **`IAuthProvider`** — контракт OAuth
- **`CloudItem`** — единая модель файла/папки (никогда не раскрывает DTO провайдера)
- **`DownloadInfo`** — URL + заголовки для авторизации скачивания

Каждый провайдер находится в своей папке с **Provider**, **AuthProvider**, **ApiClient**, **Mapper** и **Config**.

## 🔐 Аутентификация и безопасность

- **Поток Authorization Code в OAuth 2.0 с PKCE (S256)** для всех трёх провайдеров
- **Нет клиентских секретов** в бинарниках OneDrive и Dropbox (публичные клиенты PKCE)
- Google требует клиентский секрет из-за типа OAuth-клиента «Web application»
- Токены хранятся в **HarmonyOS Asset Store**, разбитыми по 900 байт, чтобы обойти ограничение в 1024 байта на значение
- `TokenRefresher` прозрачно обрабатывает 401 с автообновлением
- Проверка параметра state предотвращает CSRF
- Связь только по HTTPS

## 📦 Начало работы

### Предварительные требования
- DevEco Studio 26.0.0 или новее
- HarmonyOS API 26 SDK
- Аккаунт разработчика Microsoft, Google или Dropbox

### Зарегистрируйте собственные OAuth-приложения

CLDrive — публичный OAuth-клиент, и каждый пользователь регистрирует своё приложение в консолях трёх провайдеров. Так каждый пользователь полностью контролирует свои учётные данные.

**Azure (OneDrive)**
1. Azure Portal → Регистрация приложений → Новая регистрация
2. Поддерживаемые типы аккаунтов: Мультитенантные + личные аккаунты Microsoft
3. URI перенаправления: Платформа «Мобильные и классические приложения» → `https://cl.drive/oauth`
4. Дополнительные параметры → Разрешить потоки общедоступного клиента: **Да**
5. Делегированные разрешения: `Files.ReadWrite`, `User.Read`, `offline_access`

**Google Cloud (Google Drive)**
1. Google Cloud Console → APIs и сервисы → Учётные данные → Создать OAuth-клиент
2. Тип приложения: **Веб-приложение**
3. Авторизованный URI перенаправления: `http://127.0.0.1:8080/oauth2redirect`
4. Включите Google Drive API

**Dropbox**
1. Dropbox App Console → Создать приложение
2. Доступ с областями → Full Dropbox
3. OAuth 2.0 → URI перенаправления → `https://cl.drive/dropbox-oauth`
4. Разрешения: `account_info.read`, `files.metadata.read`, `files.metadata.write`, `files.content.read`, `files.content.write`

### Сборка

```bash
git clone https://github.com/sharjeel-butt/CLDrive-HOS
cd CLDrive-HOS
# Откройте в DevEco Studio, затем запустите на устройстве или эмуляторе
```
